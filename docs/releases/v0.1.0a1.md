# CloudMarks v0.1.0a1 — experimental read-only viewer

Licensed under MIT.

Initial experimental release candidate for a dedicated disposable OneDrive test
account on Ubuntu 26.04 / GNOME Files 50. It combines verified complete-file offline
storage, read-only views and a status-only Files adapter. This candidate is not
intended for important/personal data or daily deployment.

Explicit CLI commands download/verify files, preserve pin intent, retry durable
jobs, check stable cloud identities and maintain bounded folder manifests.
Conflicts preserve versions and block replacement; there is no automatic merge
or in-place repair. Local eviction requires fresh matching cloud evidence and
never deletes a cloud file. The production backend implements reads/downloads
only. The opt-in M4 test harness alone mutates its own disposable cloud fixtures.

No offline editing, uploads, automatic watcher/sync, mounted updates, placeholder
catalog, empty-directory publication or context-menu actions are included. The
adapter and its IPC remain read-only. All byte-changing controls require the
experimental view unmounted. Stale evidence shows unknown even when retained
snapshots are readable. Display verification is limited to 8 MiB; recursive
intent supports 128 entries, while aggregate badges support 64 files / 8 MiB.

Physical network/disk unplug/replug, full logout/login, larger real files and
readability/accessibility acceptance remain pending. Previous proxy-loss/restart
checks are documented simulations rather than those hardware tests. See the
bundled `docs/operations.md`, `docs/compatibility.md`, `docs/release-checklist.md`
and milestone validation records before configuring a test profile.

The wheel installs only the CLI/library; no service, mount, account authentication,
system package or desktop extension is enabled automatically. The source archive
includes templates, tests, documentation and sanitized historical evidence.
`SHA256SUMS` covers the wheel and source archive; it is not a publisher signature.

Publication requires the selected license in LICENSE/metadata and a matching
committed/tagged source with successful CI. A deliberate version tag triggers experimental prerelease publication after
validation; branch pushes never publish. Publication status and run evidence are
recorded separately in the repository release page and M5 handoff.
