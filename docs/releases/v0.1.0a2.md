# CloudMarks v0.1.0a2 — guided setup and offline controls in Files

Licensed under MIT. **Experimental:** use a test account or a folder of
disposable files, and keep backups of anything important.

## What's new since v0.1.0a1

- **Guided setup.** `cloudmarks setup` signs in through rclone in your browser,
  confirms the account, lets you pick a OneDrive folder, creates the Upload and
  Offline folders, installs the Files extension and creates three user services.
  It resumes after an interruption and never overwrites existing files.
- **Health checks.** `cloudmarks doctor` reports on requirements, installation,
  folders, services and store health. The report is safe to paste into an issue.
- **Keep offline and Free local copy in the Files menu**, for files and complete
  folders, with a progress window that can cancel and retry.
- **Upload observation.** Files copied into the Upload folder show Uploading,
  then Cloud only once OneDrive confirms them.
- **Folder badges** require current cloud membership and verified local copies
  for every file, including nested and empty folders.
- **Optional live updates** let Keep and Free run while the Offline folder stays
  open. Without them, a busy folder now names the applications using it.
- **Privacy-filtered diagnostics** through `cloudmarks logs`.
- A plain-language [user guide](../user-guide.md) and configuration and command
  references.

## Install

```bash
sudo apt install python3-nautilus gir1.2-nautilus-4.1 gir1.2-gtk-4.0 fuse3 pipx
sha256sum --check SHA256SUMS
pipx install ./cloudmarks-0.1.0a2-py3-none-any.whl
cloudmarks setup
```

rclone 1.75 or newer is required separately. Tested on Ubuntu 26.04 with GNOME
Files 50.2.2 and rclone 1.75.2.

## Upgrading from v0.1.0a1

Setup is for new installations; it refuses to replace an existing one. Existing
manual profiles keep working. Follow the
[upgrade procedure](../operations.md#upgrade-and-rollback) and back up the
store, state and configuration together first: **the first write upgrades the
state database to schema 5, which v0.1.0a1 cannot read.**

## Known limits

- Physical network loss, disk disconnection and logout/login acceptance tests
  are still pending; see [physical acceptance](../dev/physical-acceptance.md).
- Live updates are opt-in. Their filesystem behaviour was measured with a local
  stand-in for OneDrive ([ADR 0002](../decisions/0002-live-view-updates.md)).
- Only consumer OneDrive on GNOME Files was validated. OneDrive Business, shared
  folders, other desktops and other Nautilus versions are untested.
- No offline editing, two-way sync or automatic conflict merging.

`SHA256SUMS` covers the wheel and source archive; it verifies the download, not
the publisher's identity.
